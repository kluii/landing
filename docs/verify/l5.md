## 2. Mobile overflow (390 px)

- Root cause reproduced on the L4 build before any fix: at 390 px, `document.documentElement.scrollWidth 485` vs `clientWidth 390`; overflowing elements: `code-block right=485`, `code-header right=484`, `copy-btn right=472`, `install-steps right=485` — the `.install-grid` track's min-content floor set by the `<pre>`.
- Fix: `grid-template-columns: minmax(0, 1fr)` in the `max-width: 1023px` media query of `InstallSection`/`EndSection`/`AgentsSection` (the desktop tracks were already `minmax(0, …)`), plus `min-width: 0` on the grid/flex children (`.install-steps`, `.agents-copy`, `.end-copy`).
- Guard: `e2e/responsive.spec.ts` — 390/768/1440 × [`/`, `/selfhosted`, `/fr`, `/fr/selfhosted`, `/docs/v2/quickstart`], asserting `scrollWidth === clientWidth` and no element `right > viewport` unless the element or an ancestor is a scroll/clipping container or fixed-positioned. Result: `25 passed`. Manual spot check after the fix: 390 px on all four landing routes → `scrollWidth/clientWidth = 390/390` on each.
- Found by the new gate, fixed in this wave: `/fr/` (trailing slash) 404s under `trailingSlash: 'never'` — the FR route is `/fr` everywhere now (links, canonical, e2e); and `HAS_FR_ROUTES` (an `existsSync` on the bundled `import.meta.url`) evaluated false at build time and silently pointed the FR nav docs link at the EN docs — now a constant asserted by the i18n test.
